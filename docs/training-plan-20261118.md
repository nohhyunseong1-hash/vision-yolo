## 4. 학습 실험표

목표 구성은 **가벼운 사람 모델 + 머리 상태 모델 + 몸통/조끼 상태 모델**, 필요할 때만 자세 보조다. 지금의 큰 사람 모델은 정확도 비교 기준 및 조건부 교사 후보로 보존한다. 처음부터 5개 모델을 항상 실행하는 구조에 새 모델을 더 붙이지 않는다.

| 단계 | 실험 | 초기 설정 | 진입/종료 조건 |
|---|---|---|---|
| A: 재현·smoke | 정제 데이터, 신규 run ID, 각 task 2–3 epoch | 공식 초기값 hash 확인, AMP, GPU 1개 | 라벨/클래스/원본 좌표/NaN/VRAM 확인 후 다음 단계 |
| B1: 사람 탐색 | YOLO26n/s × 960/1280 = 4개 | 각 10–20 epoch, 동일 데이터·seed·평가 그룹 | 작은 사람 recall과 지연을 함께 비교해 1–2개 선택 |
| B2: 머리 탐색 | YOLO26n/s = 2개 | 640, helmet/bare_head, 각 10–20 epoch | 착용·미착용 혼동, 작은 머리, 일반 모자·설비 오검출 비교 |
| B3: 조끼 탐색 | YOLO26n/s = 2개 | 640, vest/no_vest, 각 10–20 epoch | bbox 대상 일관성 확인이 선행. 전신 라벨이면 상태 분류+관측 torso 방식 별도 평가 |
| C: 본 학습 | task별 승자, 필요 시 2위 추가 | 100–150 epoch, 개선 중인 후보만 최대 200; patience 20–30 | validation 목적함수·학습곡선·클래스별 PR 기준으로 조기 종료 |
| D: 안정성 | 최종 후보를 추가 seed 2개로 반복 | seed 101/202/303, split 고정 | 최선 seed 하나만 보고하지 않고 평균·분산 및 최악 클래스를 비교 |
| E: 경량화 | n/s 직접 학습 결과와 교사 증류 비교 | 실제 이점이 입증된 경우만 | 정확도 손실 대비 4채널 관측률 이득이 있는 후보만 유지 |

세부 원칙:

- person의 특징 추출부를 계속 동결하지 않는다. 초기 3–5 epoch 안정화 후 뒤쪽 특징층, 이어 낮은 학습률의 전체 미세조정을 비교한다. BN 통계 동결/갱신도 train 데이터에서만 비교한다.
- AdamW, `lr0` 1e-4–5e-4 범위의 작은 탐색, warmup 약 3 epoch, cosine LR를 출발점으로 삼는다. 이는 확정 최적값이 아니다.
- batch는 고정 24를 모든 입력 크기에 강제하지 않는다. 16GB 개발 GPU에서 smoke로 올려가며 최대 사용량 약 12–13.5GiB 안의 안정 batch를 정한다. accumulation을 포함한 유효 batch를 기록한다.
- 원거리 크기 축소, 약한 blur/JPEG, 밝기/대비, 상부 시점에서 유효한 변형을 비교한다. raw/median 혼합은 train 자료에만 적용하고 반드시 ablation을 남긴다. 정보를 지워버리는 과한 mosaic/회전은 피하고 마지막 10–20 epoch는 mosaic을 끈다.
- PPE 학습의 물체 크기와 주변 문맥을 실제 person crop 추론에 맞춘다. 완전한 person 정답이 있는 자료의 crop과 원본을 섞되, 다른 사람의 보호구를 잘라 포함한 crop을 잘못 연결하지 않는다.
- 증류를 한다면 **기존 라벨이 있는 train 이미지에서만** 사용한다. 사용자 CCTV의 의사 라벨을 만들지 않는다. 교사가 해당 검증 구간에서 학생보다 실제로 나을 때만 적용한다. Ultralytics의 단일 옵션으로 구현돼 있다고 가정하지 않고 별도 trainer/손실 검증이 필요한 선택 단계로 둔다.
- 각 run에 source commit, 패키지 버전, 초기/부모/최종 weight hash, manifest hash, seed, optimizer, 입력 크기, 실제 GPU 시간, 최고 VRAM, 중단 사유를 남긴다. `best.pt` 선택은 validation으로만 하고 test로 checkpoint를 선택하지 않는다.

현재 archive trainer의 해상도·freeze·LR 일부는 하드코딩돼 있다. **실행 전에** 이 항목을 공통 CLI/설정으로 노출하고, 기존 run을 덮어쓰지 않는 실행 큐와 resume/NaN/OOM 중단 기록을 추가해야 한다. 이 문서를 실행 가능한 자동 학습 스크립트라고 취급하지 않는다.

## 5. 평가와 교체 기준

### 정확도

- 고정 기존 test와 신규 source-group holdout에서 클래스별 precision/recall/AP50/AP50–95를 측정한다. 원본 해상도·source별로 사람/머리 크기 구간(<32, 32–64, 64–128, ≥128px)도 보고한다.
- `helmet ↔ bare_head`, `vest ↔ no_vest`, 배관/설비 FP, 미착용자를 착용자로 잘못 판정하는 오류를 따로 집계한다. 양성만 많아진 모델을 무조건 채택하지 않는다.
- score threshold와 시간 확인 조건은 validation에서 정한다. 판단불가를 분모에서 조용히 빼지 않고 판단 범위/unknown 비율을 함께 보고한다. 새 프레임 관측 공백, ID switch와 fragmentation도 확인한다.
- 크레인 두 영상은 학습 제외 회귀 시험이다. 평가 주석이 필요하면 평가 전용으로 분리하고 학습에 재사용하지 않는다. 이미 반복 진단한 영상이므로 독립 blind test라고 부르지 않는다.
- 근거리 영상의 PERSON+NO-HARD HAT+NO-VEST 표시와 착용 오판을 확인하고, 원거리 다중 객체와 실제 NO-VEST 검출이 개선됐는지 샘플/구간별로 검토한다. 사람 프레임 수만으로 검출률을 주장하지 않는다.
- 같은 출처의 미라벨 사람이 확인되면 라벨 정리 없이 학습량을 늘리지 않는다. 허용된 데이터만으로 원거리 조끼를 해결하지 못하면 부족한 장면/라벨을 구체적으로 보고하고 실패 후보를 등록하지 않는다.

### 속도와 안정성

1. 새 n/s 모델의 PyTorch CUDA FP16 기준선을 먼저 재고, 전체 모델 조합의 비용을 측정한다.
2. 가장 비싼 X 다중 시야를 작은 모델 1회 분석으로 대체할 수 있는지 확인한다. 조건부 crop·입력 해상도·batch를 바꾸더라도 필수 클래스별 **실제 새 관측률**을 따로 기록한다.
3. 선택된 모델만 ONNX/TensorRT FP16으로 export한다. 같은 입력/letterbox/NMS/threshold/max_det 조건에서 원본과 box·score·클래스·PPE 상태 동등성을 확인한다.
4. TensorRT engine은 최종 RTX 5070 Ti **Laptop** 장비에서 생성·검증한다. 데스크톱의 `.engine`을 그대로 호환된다고 가정하지 않는다. INT8은 FP16보다 추가 이점이 있고 미착용 recall 손실이 허용 범위일 때만 후속 검토한다.
5. 1→2→4채널, 브라우저 연결 상태에서 30분→2시간 운용한다. 미리보기 FPS, inference FPS, 원본 박스의 시간차, 수신→표시 p95, 큐/드롭/VRAM/RAM을 분리한다. 파일 재생·정지 사진 DEMO·실물 카메라 측정도 구별한다.

사용자가 처음 정한 정상 목표를 유지한다: 대상 노트북 **4채널 각 15 새 관측 fps 이상**, 타일 미리보기 10–15fps, host 수신→브라우저 표시 p95 ≤500ms, VRAM ≤9GB, 시스템 RAM ≤20GB, 처리 기아·OOM·지속 증가 없음. 화면만 25–30fps가 된 것은 통과가 아니다.

현장 정답이 확보됐을 때의 초기 목표도 유지한다: 중요한 침입/근접 이벤트 recall ≥95%, PPE 미착용 recall ≥90%, 이벤트 precision ≥95%, 오경보 ≤1건/카메라·시간. 지게차 완성 라벨과 실제 현장 이벤트 정답이 현재 없으므로 이 항목 전체의 통과를 약속하지 않는다. 목표 미달이면 기준을 낮추지 않고 실측과 원인을 남긴다.

## 6. 일정과 자원 배분

첫 캠페인의 계획 범위는 데이터 점검 약 1일, 탐색 약 반일~1일, 본 학습·seed 반복 약 1–3일, 평가·export·운용 시험 약 1일이다. **계획상의 추정**이며 아직 측정한 완료 시간이 아니다. 가장 먼저 2–3 epoch의 실제 step 시간을 측정해 `steps/epoch × epoch × 초/step`과 검증 비용으로 일정을 다시 산정한다.

첫 캠페인은 최대 72 GPU시간을 계획 상한으로 두고 단계별로 성과를 확인한다. 모든 조합에 200 epoch를 돌리지 않는다. 성능이 멈추거나 regression이 생긴 후보는 중단하고, 유효한 후보에 본 학습과 seed 반복을 집중한다. 추가 캠페인은 결과에 따라 데이터/구조/속도 병목을 바꾼 뒤 설계한다. 지금 이 상한만큼의 실행이 시작됐다는 뜻은 아니다.

제공 산출물: 데이터 감사·고정 split, run별 provenance/곡선/혼동 사례, 검증된 새 `.pt`, 별도 모델 registry, 두 실제 영상의 전후 비교, 대상 장비 성능표, 채택/미채택 이유, 가중치 Release 및 되돌리기 기준. 기존 모델은 새 후보가 정확도·속도 회귀 검사를 통과할 때까지 보존한다.

## 7. 이번 통합 검증

자동 검사 71개 및 실제 CUDA 모델을 사용한 HTTP/MJPEG/WebSocket/이벤트 통합 검사 9개 통과. 첫 테스트 실행의 2개 실패는 실행 중인 기존 서버가 프로젝트 단일 실행 잠금을 보유해서 발생했으며, 해당 프로젝트 서버만 정상 종료한 뒤 전체 검사를 다시 통과했다. 테스트 통과를 검출 정확도 향상으로 해석하지 않는다.

같은 산업 파일을 4채널로 재생한 45초 측정(초기 10초 제외)은 채널당 새 검출 평균 **3.94fps**, 미리보기 **23.94–24.03fps**, 표시 박스의 원본 분석 프레임과의 시간차 p95 **843–844ms**, 큐 최대 1개였다. 원거리 사람 모델을 포함한 기존 5개 모델을 유지한 수치이며 아직 정상 목표 15fps에 못 미친다. JSON은 `docs/live-preview-integration-20261118.json`에 있다.

raw live preview의 디코딩 완료→인코딩 p95는 약 16ms이지만 **추론을 기다리지 않는 화면 경로만** 측정한 것이다. 이전 analysed-frame preview 지연과 같은 지표로 비교하거나 전체 안전 판단 지연이라고 보고하지 않는다. 이전 2.01fps 시험과는 시간·주변 부하가 달라 통제된 배수 개선 효과도 주장하지 않는다. 브라우저·실물 카메라·대상 노트북은 이번 측정에 포함되지 않았다. 실행 중이던 기존 DEMO 채널은 검증 후 일시정지 상태로 복원한다.
